## Commit Messages

This project uses a simple structured commit format. Release notes are generated by `.github/scripts/changelog.sh`, which groups commits by their type.

Format:
- feat(scope): short description
- fix(scope): short description

Rules:
- feat → appears under Features in releases
- perf → appears under Performance Improvements in releases
- fix → appears under Bug Fixes in releases
- refactor → appears under Refactors in releases
- docs → appears under Documentation in releases
- Any other type (e.g. ci, chore, build, style, test) → appears under Other Changes
- Optional body is allowed
- Scope is optional but recommended
- `!` after the type/scope marks a breaking change (e.g. `feat(api)!: ...`)

The type/verb is dropped from the release notes (the section already says it). A
scope is kept as a prefix:
- `feat(ui): add dark mode` → `- ui: add dark mode`
- `fix: stop a crash` → `- stop a crash`

Examples:
- feat(proxy): support keep-alive for plain HTTP forwarding
- fix(socks): handle SOCKS5 REP errors during handshake
- perf(ui): stop telemetry ticks from re-rendering the whole app
- docs(readme): document the config schema
- feat(ui): add per-host breakdown chart
