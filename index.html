Run the tunnel for me

No tunnel yet? Let the app run one.

Already have a SOCKS5 proxy? Point at it. Don’t? Give Proxy Manager your SSH host and it runs and supervises the tunnel for you — restarting it automatically if the connection drops.

  • Key-file or password auth; the password is stored in the Keychain, never in the config.
  • Automatic restart with backoff, and a one-click Restart tunnel.
  • Auth, host-key, and key-file errors are surfaced instead of retried forever.

How it works

One local hop decides where each connection goes.

Apps & CLI browser · curl · node
→
Local proxy 127.0.0.1:8888
→
App rule → tunnel all · direct all
Host allow-listed → SOCKS5 tunnel
Everything else → direct
  1. Turn it on. One switch starts the proxy, sets the macOS system proxy, and exports HTTP_PROXY/HTTPS_PROXY for CLI tools.
  2. Traffic is classified. Each connection is matched to its app first (Tunnel all / Direct all), then to the host allow-list; everything else goes straight out, streamed with backpressure.
  3. Watch it work. Every request shows up live. Turning it off restores your original settings.

Under the hood

  • Raw sockets, not a framework. Outbound connections use connect(2) directly, so they never re-enter the system proxy this app sets.
  • Streaming, not buffering. CONNECT tunnels are relayed byte-for-byte with backpressure, so SSE and LLM token streams arrive as they are produced. WebSocket sessions (ws:// and wss://) relay full-duplex too.
  • Bounded memory. Fixed 256 KB buffers per direction, with half-close handled so responses are never truncated.
  • Telemetry off the hot path. Per-request recording is a lock and an append; a single batched writer flushes SQLite.
  • Per-app identity, resolved locally. With per-app routing on, each connection is matched to its originating app by a local process scan — helpers resolve to their host app. Off by default, so the hot path is unchanged.
  • Crash-safe. A watchdog restores your original proxy settings in milliseconds if the app dies.
  • Loopback by default. The proxy binds to 127.0.0.1 and blocks non-loopback clients from private destinations.
  • No admin prompts. Proxy toggles use per-user settings, so a normal setup never asks for a password.

Private by design

  • No TLS interception. CONNECT streams are relayed byte-for-byte.
  • Local-only. Binds to 127.0.0.1; private destinations are blocked for non-loopback clients.
  • Metadata only, on disk. Host, app, size, timing, and status in a local SQLite file. No bodies or headers.
  • Secrets in the Keychain. An SSH password is never written to the config or a command line.

Questions

macOS won’t open the app — is it safe?

Proxy Manager isn’t notarized by Apple, so macOS may block the first launch. Open System Settings → Privacy & Security and click Open Anyway for Proxy Manager. You only need to do this once; the app updates itself normally afterwards.

Do I need my own server or tunnel?

Yes — Proxy Manager routes to a SOCKS5 proxy that you provide. Make one with ssh -D 1080 user@host, or switch on “Run the tunnel for me” and let the app create and supervise the SSH tunnel.

What is a SOCKS5 proxy?

A lower-level pipe that carries traffic to a remote machine. Your apps speak HTTP to the local proxy; the local proxy speaks SOCKS5 to your tunnel, so CLI tools that can’t do SOCKS5 directly still work.

Does all my traffic go through the tunnel?

No. Only the hostnames on your allow-list — plus any apps you set to Tunnel all. Everything else connects directly, so the rest of your browsing is unaffected.

Can I route traffic per app?

Yes. In Settings → Apps, each app can be set to Tunnel all, Use target rules (follow the host allow-list), or Direct all, and apps with no rule use a default you choose. You can also set the frontmost app's mode straight from the menu bar. It's off until you turn it on.

Will it work with curl, node, and other CLI tools?

Yes. It writes HTTP_PROXY/HTTPS_PROXY into your shell rc files, so new terminal sessions route through it automatically.

Does it work with WebSockets?

Yes. wss:// (WebSocket over TLS) is carried by the same opaque CONNECT tunnel as other HTTPS traffic, and ws:// upgrades are forwarded, so the origin switches protocols and frames flow both ways for the life of the connection.

Is this a VPN?

No. It’s an allow-list HTTP proxy, not a system-wide tunnel or packet-level VPN. It never touches traffic that isn’t on your list.

What happens if the app crashes while routing is on?

A tiny crash watchdog restores your original proxy settings within milliseconds, so your internet is never left pointing at a dead local port.

How do updates work?

Proxy Manager checks for new versions via Sparkle in the background and always asks before installing. You can change the frequency or turn checks off in Settings → General.

Can the app see my traffic?

No. TLS is passed through untouched; only metadata (host, size, timing, status) is recorded, and only on your disk.

Route what you choose. Leave the rest alone.
